# GrayMatter blended profile security: implementation and limits

The source implementation is in GrayMatter `main`, with the necessary canonical authorization integration in ValkyrAI `rc-7`. The behavior and evidence below describe the source implementation prepared on 2026-10-07. Existing unrelated work is preserved. Production DDL, grants, credentials, and deployed security configuration are unchanged. Publication and deployment require separate review.

The original local blend concatenated results from separately selected profiles without a common authenticated actor, organization, or composition decision. Profile names and account fingerprints were routing metadata. Deferred operations recorded an API URL and body digest, but replay could adopt the current account and destination. In the MCP receipt projection, a caveat could permit denied or stale evidence; missing policy could retain source bodies. Private MCP tenant overrides and identity-bearing arguments could also reach upstream requests.

The patch uses the existing scoped identity factory, permission evaluator, AclService, tenant resolver, and retrieval-domain policy. It does not introduce a second ACL system.

| Boundary | Enforced behavior | Maintained source |
| --- | --- | --- |
| Source READ | Independently required for every composed source. | ValkyrAI `CompositionAuthorizationService`, existing canonical permission evaluator |
| Source MERGE/COMPOSE | New sources additionally need an explicit canonical `MERGE` grant, bit 2048. Ownership, administration, and READ alone do not supply it. | ThorAPI `ValkyrAIPermission`, `ValkyrAclSecuritySupport`; ValkyrAI `AclService`, `GeneratedObjectAclGuard` |
| Source lifecycle | A real persisted legacy row retains existing behavior; unavailable, absent, or unknown lifecycle state denies composition. | Both maintained JavaSpring `pojo.mustache` templates; `AclService.compositionRequirement` |
| Profile assembly | All participating local profiles must resolve to the same live API-confirmed actor, organization, schema, registry, and API base. Required source receipts must still be valid at assembly. | GrayMatter `gm-source-authority`, `gm-profile-lib` |
| Model projection | Retrieved evidence is untrusted data. Blend evidence is bounded; authorization and source receipts stay in MCP `_meta`. Denied, stale, unknown, or missing receipt policies withhold source bodies. | GrayMatter `mcp-server/index.js` and packaged mirror |
| Action/destination | Blended mutation and export-link operations are denied. Deferred writes require unchanged authenticated source/destination bindings, body integrity, and the destination API's own authorization. | GrayMatter `graymatter_api.sh`, `gm-replay-deferred` and packaged mirrors |

`MERGE` is distinct from READ, WRITE, and publication. `COMPOSE` is its alias. Existing OWNER mask 49 and ordinary ACL behavior are unchanged. A public template cannot grant rights to private inputs or to an output destination. Existing anonymous/everyone grant restrictions remain intact; new public sources need a permitted authenticated explicit MERGE grant under those existing rules.

New-versus-legacy classification comes from `server_composition_policy_version`, a private JPA field with `@JsonIgnore`, no accessor, and an immutable column mapping. `@PrePersist` always sets `MERGE_REQUIRED_V1` for an actual insert, including imported IDs, copied Java objects, cascaded children, and rollback/retry. Existing updates do not stamp or backfill a legacy row. A metadata-stripped update cannot downgrade an existing stamped row. Source existence and the persisted marker are read through the canonical scoped identity; a caller's timestamp, null field, provenance, ACL metadata, or omitted request property cannot classify a source as legacy.

The same generated lifecycle stamp distinguishes a current explicit MERGE ACE from an old wide mask. Negative masks, unknown permission bits, missing markers, and old unversioned granting ACEs cannot accidentally gain MERGE when the new bit is named. An explicit new MERGE grant creates a current ACE rather than rewriting an old entry. Existing deny entries still apply. ACL lookup failures fail closed for MERGE.

The model-only regeneration produced 703 JPA entities and all 703 contain the insert stamp. That count describes generated JPA coverage, not all possible writers or external source types. Generator templates were changed; generated models were regenerated rather than edited by hand.

The canonical preflight handler now accepts `operation=composition.authorize` with one to fifty exact UUID/type references, bounded to 16 KiB and restricted to the maintained tenant GrayMatter model catalogue. It independently checks source READ and the lifecycle-dependent MERGE requirement. The response binds exact source attribution, tenant scope, `retrieval-context` purpose, policy version, a receipt ID, and a 30-second expiry. It expressly reports `destinationAuthorized=false`. The local profile client validates every dimension, rechecks identity after retrieval, and intersects receipt lifetimes once more before releasing assembled evidence. Missing attribution, failed reads, missing policy, denial, changed scope, or expiration releases no partial source bodies.

Different actors, organizations, schemas, or API authorities cannot be combined by the generic local profile path. Existing server-side `OmegaRetrievalDomainRuntimeService` remains the route for governed domain composition, with its canonical plan, scope, approval, residency, and egress checks. This patch does not invent trust from multiple credentials. It does not establish a new arbitrary cross-organization composition bridge or prove every existing broker route with the new MERGE requirement end to end.

`RetrievalReceiptRuntimeService` applies the composition gate while selecting readable candidates, before reranking or context assembly, and when reauthorizing cached receipt sources. Semantic-index results use the actual target identity. Existing `ContextPageRuntimeService` calls the same recheck when materializing or reusing a page. Existing `ContextPagePromptCompiler` already marks task and evidence as untrusted and compiles a bounded projection. Input filtering and framing are defense in depth; retrieved instructions do not become grants or trusted control-plane instructions.

Private MCP rejects tenant/organization/user/owner override headers and nested identity, profile, permission, or lifecycle overrides in memory/retrieval arguments. The decoded token tenant is only a routing hint; the upstream server's authenticated token verification remains authoritative. An explicit client tenant hint must agree with that session hint. No client-supplied tenant becomes an impersonation grant.

Deferred queue records now contain the API-confirmed source binding as well as API base and body digest. Replay validates current authority before reading a body for transmission and before each operation. Changed actor, organization, API destination, unavailable tenant context, unauthenticated sessions, missing bindings, and body tampering preserve the queued record and send no write. The former skip-preflight flag cannot bypass this check. Legacy fallback records and records created without verified authority are preserved locally and denied automatic adoption by a newly active profile. Successful replay still depends on the destination API accepting the independently authenticated mutation.

Verified evidence as of 2026-10-07:

- MCP: 186 tests passed, zero failures, including denied/caveated/stale/missing policy suppression, nested organization impersonation rejection, and bounded blend evidence with receipts outside model content.
- ValkyrAI focused native suite: 171 tests passed, zero failures/errors: 85 ACL grant cases, 67 retrieval cases, 13 preflight cases, four composition cases, and two actual Hibernate/H2 lifecycle tests.
- ThorAPI permission suite: nine tests passed, zero failures/errors.
- Profile fixtures passed authorized same-authority aliases, denied/missing/stale policies, missing attribution, unauthorized organization mixes before body retrieval, expiration during assembly, and blocked memory/media-link actions carrying injected instructions.
- Replay fixtures passed ten source/destination cases, including authorized replay, scope changes, missing authority, tampered body, rejected destination write, and legacy fallback preservation. API and release-surface/mirror tests passed. Both repositories passed `git diff --check`.

These tests use synthetic identities, local HTTP fixtures, and isolated H2 databases. They do not establish production authorization, live cross-organization composition, or release readiness. Test logs, owned-source patch snapshots, source hashes, and the generator coverage receipt accompany this note in the delegated task evidence folder.

Deployment is deliberately unresolved. Each applicable generated entity table needs a separately reviewed nullable-column schema expansion with no legacy default and no backfill, followed by coordinated writer cutover. A missing column or unreadable lifecycle state denies composition and can prevent normal ORM access. Older writers or non-JPA SQL/import tools can insert a null marker and defeat reliable new-only classification; mixed writer versions require separately reviewed insert enforcement or exclusion. The already-dirty rc-7 application configuration defaults Hibernate DDL handling to `update`; release must prevent unreviewed implicit production schema changes. No such changes were performed by this task.

Remaining boundaries are explicit. Generalized derived-output reader intersection and egress enforcement across every workflow, ExecModule, direct LLM call, publication, export, and memory sink are not established by this patch. Source MERGE and destination WRITE alone do not prove that every output reader may read every input. Non-generated/non-JPA/external sources and alternative generated application runtimes need deliberate integration. The Lite server currently lacks the canonical authority/composition projection needed by this client path, so unsupported blends fail closed until that server supplies it. Cached or model-retained evidence cannot be recalled after disclosure; subsequent governed reads are rechecked.

Hosted retrieval adapters send selected redacted and bounded snippets to approved remote providers. `HostedProviderPayloadPolicy` is selective disclosure shaping, not literal data residency or an exhaustive secret detector. Prompt framing and input filtering cannot guarantee zero injection or confused-deputy risk. The defensible article claim is that specific authenticated source, composition, receipt, and replay boundaries now have code enforcement and regression evidence, with release and universal output controls still requiring work.

Automatic approval review rejected an attempted general public MERGE grant extension as an authorization weakening. That extension was not applied. The implementation retained existing public grant rules and continued with authenticated explicit grants.
